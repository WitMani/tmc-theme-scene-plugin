# theme-stage2 · 主题素材工坊

美术生成 Stage 2：从一张 Stage 1 成品图，制作独立背景与代表性素材。与 `theme-scene-studio` 的 Stage 1 候选生成分开使用。

## 默认结果

- 1张独立背景PNG。
- 22种独立素材PNG：建筑8、道具6、载具3、角色5；用户明确覆盖优先，源图不足须报告缺口。
- 只交付图片，不默认制作HTML、原图对照、额外报告或回拼。

正式版采用美术规则 **1.6.0**：背景默认B档大形体分面，同时合并内部小形状与纹理，物件保持 V2 生成逻辑。V3 单次试验的附加反面图和加强 Prompt 不纳入默认流程。

素材V2遵循日韩卡通、正交等距、角色约2头身、逐部件邻近色描边、克制但可读的体积，以及可见卡通夸张。背景概括叶簇、树皮、草纹颗粒和砖木缝，以较少低对比宽色面表现地形、岸壁、桥体和植被厚度，避免扁平或厚重3D；内部优先保留连续可排布空间，非交互树木、灌木及石堆允许删减并向画布外缘归并；保留水流泡沫与柔和环境层次；尽量去掉围栏、矮墙和装饰包边，保留必要地形侧面及桥体连接。

背景规则与本次 E/B 改进记录见 [背景 B 档](runtime/docs/BACKGROUND-B-RENDERING.md)。

背景排布与验收见 [可排布空间规则](runtime/docs/BACKGROUND-PLACEMENT-SPACE.md)：外围装饰适量且不围成墙，内部地块不包边，道路、岔口与桥头保持净空。

## 使用

在新任务中附上一张 Stage 1 成品图：

```text
使用 $theme-stage2，处理这张图，只输出背景和默认22种素材 PNG。
```

也可继续已有运行，定向修正未通过的素材。缺少源图时不会套用内置威尼斯案例或其他默认图片。

## 生成速度

默认全量并发：输入准备完成后，一次性提交全部素材和背景的独立请求，默认22种素材＋1张背景共23个。不人为分成4张或8张批次；遵从工具明确上限，明确限流时才逐级降档。共用记录串行写入，最终统一尺度与验收。实际速度受图像服务排队影响，不保证固定加速倍数。

## 随包能力

技能负责执行编排；`runtime/` 包含选材、生成记录、透明化、图像绑定复核和图片导出代码。规范及用户补充快照随包携带，正常运行无需读取原开发工作区或登录飞书。

生成使用 Codex 内置图像工具，CLI 不调用图像生成 API。本地处理需 Python 3.10+、Pillow、NumPy、SciPy：

```bash
python3 scripts/run.py doctor
python3 scripts/run.py --help
```

具体命令见[执行流程](skills/theme-stage2/references/workflow.md)。脚本可从任意工作目录通过绝对路径调用。

## 质量与范围

真实alpha只是文件条件，风格仍需逐项观察。规范或图片变化使旧复核失效；未通过结果不标为正式合格。遮挡结构属于推断补全，不保证像素级逆向、几何锁定或自动风格评分。

示例清单仅用于字段示意和回归，不是新主题的资产清单。本插件不负责Stage 1主题生成、场景摆放、动画、碰撞或玩法导出。

## 开发与验证

本插件目录包含完整开发源文件。修改源目录后，用个人插件的缓存版本更新与重装流程生效；不要把安装缓存当开发源码。

```bash
python3 -m unittest discover -s runtime/tests -v
```

测试使用合成图像，不调用付费生成。历史艺术样本或合成测试的通过记录不用于批准新素材。

## 素材尺度

Stage 2 使用[官方案例相对尺度基准](runtime/docs/ASSET-SCALE.md)，以人物1H选定逐件尺寸，并在生成后按主体包围盒等比校准。样本范围按主题使用；内部保留尺度复核，交付仍只有PNG。

## 默认与用户指定规则的优先级

未指定数量、类别或素材清单时，默认22种素材（建筑8、道具6、载具3、角色5）＋1张背景。用户明确指定时，按用户指定规则执行，覆盖对应默认约束；仅指定总数时不强套8/6/3/5配额，指定完整清单时不额外补足22种。未涉及的要求继续沿用默认。

## 一次生成交付

全部背景与素材一次性生成，内部审核不暂停生成，不弹出验收或候选选择。所有可读取的已登记PNG直接交付；审核问题和缺项仅在最终输出说明。默认不因美术问题重抽。
