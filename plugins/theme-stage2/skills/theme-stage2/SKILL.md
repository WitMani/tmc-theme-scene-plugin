# Theme Stage 2 · 独立背景与素材

目标：从一张 Stage 1 成品图得到独立背景和一组可复用素材。正常运行直接完成选材、生成与检查，不把内部清单、Prompt 或每张素材变成额外确认步骤。

## 适度审查（执行优先级）

来源：用户2026-09-22要求“整个plugin的审查规则不能过度”。本节统一下文各检查项的执行方式，覆盖默认多轮人工复审要求。

- 每阶段对同一版本产物做一次集中检查，完成即交付或进入下一阶段；将画风、尺度、基础设施等检查合并在同一次查看中。清单是关注点，不是逐条启动新一轮review的流程。
- 默认由执行者完成，不另派审核agent，不增设独立复审、打分报告、候选确认或用户验收步骤。设计任务的必要分工不等于增加审核层级。
- 只有已发现的明确问题、相关输入/产物变化或用户明确要求，才复查受影响对象及其直接依赖。未变化且依据仍有效的结论可沿用；元数据重新绑定不要求重新看全部图片。
- 保留文件可读性、真实透明、尺寸/数量契约和交接一致性等必要自动检查。默认直接运行最终交付/导出命令，由其内部执行校验；不额外反复运行相同validate。单独validate仅用于定位失败。
- 轻微美术偏好差异记录简短备注；仅对明显影响可用性或明确违反本次要求的问题做必要处理，遵守既有重试预算。未检查或未达标的结果如实标记，已有PNG仍按交付规则提供。
- 修改插件时只做与改动有关的检查；规则文字修改做格式检查即可，不自动触发全套回归、全面代码review或多轮审查。发现失败才定向重跑。


## 一次生成与非阻塞审核（最高优先级）

用户要求：不允许弹出验收，就一次性生成；审核不满意只在最终输出提到，不停止生成，不弹出候选。

- 输入齐备后一次性提交全部背景与素材，每个槽位默认只生成一次；不因美术审核自动重抽，也不询问是否重试、验收或选择候选。仅用户明确要求修正时进入修正流程。
- 某张图审核不满意或生成调用失败，不取消、不暂停其他任务；等待所有调用完成，继续透明化、尺寸处理及内部检查。
- 审核由执行者内部完成，不请求用户逐项验收，不使用选择框或候选预览作为交付前置步骤。
- 使用 scripts/deliver.py 交付所有实际可读取的已登记PNG，审核结果不阻止图片交付。最终回复提供图片，并简短列出确实存在的美术问题、未完成复核或生成缺项；没有问题则无需提示。
- 不把未通过结果写成通过；正式 Layout 合格交接包仍保留原验收门槛，但交接包受阻不能阻断本次PNG交付。
- 本节覆盖旧文档中的默认重试、候选展示和“仅验收通过才能交付图片”规则。

## 默认场景实例数量（216）

新主题的数量规划先读取[真实案例数量规则](references/scene-count-policy.md)；配置见[../../runtime/scene-count-settings.json](../../runtime/scene-count-settings.json)。默认216个摆放实例，未明确覆盖时必须大于200；这不改变独立素材种类数。按相近真实case及本次素材占地、地形容量制定逐原型数量，不把原案例的0.64倍率搬入新场景。新scene-plan必须绑定count_policy，逐项合计与target_total一致。用户明确数量和历史运行保留各自契约；普通独立PNG输入的显式一次摆放不自动扩成主题关卡。

## 固定场景尺寸与标尺

当前尺寸依据2026-09-22用户修订：**背景4096×4096；人物基体75×130 px，H=130，发型服饰道具可超出**。小物件150×150–300×300，中物件301×301–500×500，大物件501×501–830×830；大型物件地图实例数不超过待配置x。道路以车宽为1，净宽1–2.5。详细测量、例外及附件处理见[尺寸规范](../../runtime/docs/ASSET-SCALE.md)，配置见[尺寸配置](../../runtime/profiles/size-v2.json)。
英文Prompt明确square 4096×4096 delivery、ordinary character base body 75 x 130 pixels; hair, clothing and props may extend beyond。工具未提供分辨率参数时不能虚构调用参数。工具返回较小正方形图时，保留原始输出，用下述脚本等比重采样为4096交付，并保留其`.size.json`记录；这是已授权的尺寸标准化，不代表原生4K细节。非正方形结果须修正构图，不能拉伸、裁切或加边伪装完整场景。重采样不会纠正人物在画面中占比过大的问题，仍须目视检查构图标尺。

背景登记前运行 `python3 "$PLUGIN_ROOT/runtime/scene_size.py" --source "$RAW_BACKGROUND" --out "$NORMALIZED_BACKGROUND"`。新运行的validate/export会检查4096背景、H=130尺度计划和绑定当前图片及计划哈希的尺度复核；详细字段见执行流程。历史运行保留原契约，用户要求迁移时另建运行，保留原件。

## 场景交接与基础设施

先读[三阶段交接与返工](references/scene-handoff.md)。新运行必须在生图前绑定scene-plan：继承选中Stage 1候选计划，缺失时主动编制并记录数量依据。只选原型不等于只摆一次。背景清场必须保留所选素材需要的铁路、水域、道路及桥接关系；铁路不是装饰栏杆。在最终集中检查中同时核对背景基础设施，绑定实际背景和计划哈希；未经验证不得正式导出。

正式run.py export在内部export-records生成Layout交接包；普通PNG交付使用deliver.py，无需额外执行正式交接验收。PNG用户交付目录仍只含图片。交接包保存背景、透明素材、数量、核心标记、地形依赖和验收指纹；后续Layout用`init --handoff`导入。产物状态是“美术已验收，布局待验证”，不声称场景已闭环。执行命令见[流程](references/workflow.md)。

## 输入与范围

- 每个运行只有一张原始场景图，可用用户附件、明确选定的对话图或可读路径。局部裁片和修正图必须由它派生。缺图时请求补充，不使用内置示例、旧威尼斯图或其他缓存图替代。
- 多张 Stage 1 图只有在用户要求批量时才各自独立处理；不要把不同候选混成一组参考。
- 默认独立素材为22种：建筑8种、道具6种、载具3种、角色5种，背景另计1张。种类按独立原型计算，重复摆放、仅换色或镜像不算新种类；每种归入一个类别，不重复计数。用户明确清单或种类要求优先，示例清单不覆盖默认规则。此规则仅约束种类，不规定每种摆放数量、目标款数量或总实例数。逐类核对8/6/3/5，不能用其他类别补足总数冒充通过。源图不足时报告缺类与缺失原型；完整流水线回Stage 1修正，独立Stage 2请求仅报告缺口，不无依据补造。
- 同款重复、仅换色、镜像不占新名额；固定花箱和门窗留在建筑里。优先主题辨识度、轮廓/功能差异与复用价值。来源不足时报告缺口，不补造图中未见的类型。
- 用户的新要求覆盖对应默认值。讨论方案、创建插件或询问用法不触发出图。

## 美术与背景

遵循包内规范：日韩卡通、正交45度等距视图、角色约2头身。用户最新反馈优先于旧版解释；原图提供身份与主题。

正式版（美术规则 1.6.0）：独立素材沿用 V2 逻辑，背景采用 B 档大形体分面，同时合并内部小形状与纹理。V3 试验中的额外反面图和定向 Prompt 不作为默认输入或默认规则。

独立素材采用 V2 规则：
- **描边**：逐部件取紧邻填色略深的同色相。蓝部位深蓝线、绿部位深绿线、木色部位棕线、浅色部位暖灰线；不能整件套一条黑/棕/紫线。不同色区可换线色，线宽与透明度保持稳定。
- **体积**：克制但可读，保留顶/正/侧面、厚度、圆润形体与遮挡；允许少量低对比明暗面和局部接触阴影。不能压平为纸片或图标，也不做厚重3D、强黑影和高光亮边。
- **造型**：增加可见的卡通夸张，如放大屋顶、门洞、轮子或头部，主体更紧凑、圆润或有轻微弯曲；保留原型身份和功能，不破坏支撑、连接与解剖结构。
- 保持颜色明亮、细节适量、色块干净；不能将“无渐变”误解为“没有任何明暗面”。不编造文档未定义的相机角、比例容差或线宽硬阈值。

背景采用 **B 档大形体＋简洁明暗**：
- 每个连贯形体以主色和一个主要暗面说明朝向或下侧；同一结构面内不再叠加条带、小分面、树皮斑纹或亮斑。保留顶/侧、遮挡和桥岸厚度。仅用户要求 C 时增加一个宽亮面；不是全图限色。
- 同时减少内部形状数量：叶团合并为少数大轮廓，草丛芦苇按整簇概括；石块只留主要结构面，桥面省略密集砖木缝，水面保留少量宽流纹和细柔泡沫。仅降低明暗对比不算简化完成。
- 优先保障内部连续可排布空间；非交互树木、植被、石堆允许删减、归并与向画布外缘迁移，不锁定数量位置。保留地形高度、河道、桥数位置和接岸。地面保留宽阔环境色区，瀑布水花及远景氛围保留；简化内部刻画。
- `BG_VOLUME_BALANCED`、`BG_DETAIL_BALANCED`、`BG_FORM_GRANULARITY` 在同一次背景检查中记录明暗、纹理与形状粒度。已展示的 B 是比较候选，不自动视为所有项目通过。
- 具体判断与 E/B 改进记录见 [背景 B 档规则](../../runtime/docs/BACKGROUND-B-RENDERING.md)。

背景以少量外围主题植被、水流波纹、岸边泡沫、瀑布与柔和环境色差保留环境特征，不做裸地平涂地图。移除建筑、人物、载具、独立设施及多余围栏包边；保留地形分界、必要侧面、桥面桥洞与接岸。水面泡沫不属于物理包边。背景环境层次不套用素材的纯色块限制。

背景必须执行 [可排布空间规则](../../runtime/docs/BACKGROUND-PLACEMENT-SPACE.md) 与 `BG_PLACEMENT_SPACE` 检查项（并入本次集中检查）。先识别内部放置区，再清除非交互立体装饰及侵入投影；外围只留适量装饰，不把删掉的物件全部搬到边缘。“边缘”指画布外缘，不是每块内部地块边缘。道路、岔口和桥头保持净空；结构性地形例外需说明用途。此规则覆盖旧版树木数量位置保留要求。

## 素材相对尺度（必须执行）

新H130运行的尺寸配置、两轴范围、人物基体、道路比值和大型上限已经接入代码验收。必须按ASSET-SCALE.md中的可执行契约填写计划和size-review.json；正式交接包含尺寸规范快照及审核证据。


采用[当前尺寸规则](../../runtime/docs/ASSET-SCALE.md)：新尺寸分档优先；官方案例仅辅助造型与特殊对象解释，不能覆盖75×130人物标准及小/中/大物件范围。

每次运行先定H及逐件目标尺寸并保存 scale-plan.json，透明化后用 `calibrate` 命令按非透明主体包围盒等比校准并自动登记，用 `scale-contact` 生成同倍率对照后目视复核并填写 scale-review.json。不得统一每件画布占比或最长边；不得仅凭Prompt声称比例正确；命令写入的测量值不是目视结论。尺度复核通过后才正式导出；现有CLI通过不等于跨素材尺度通过。完整测量口径、130px工程默认标尺、例外与复核流程必须读取上述规则。

## 执行

1. 查看本次原图，选择代表性对象，记录原型归组、来源范围和取舍理由。按 [执行流程](references/workflow.md) 准备运行目录与英文 Prompt。
2. 使用当前可用的内置图像生成工具，每个背景或原型独立调用，默认采用**全量并发**：输入准备完成后，一次性提交本次全部素材和背景的独立图像调用（默认22个素材＋1张背景，共23个），不人为分成4张或8张批次。用户明确指定更低上限或工具明确声明上限时遵从；明确限流或并发错误时才逐级降低后续调度并发。先统一选材、尺度计划、Prompt与输入路径，再按[并发执行规则](references/workflow.md#并发生成调度)调度；独立调用不意味着串行等待。有 `imagegen` 技能时按其工具协议执行。不要用代码图形代替素材，不把一次多宫格当成多个独立资产，不擅自切换 API/CLI 生成后端。
3. 背景从原图去物、补全被挡地面并去除围栏包边；资产以原图和自己的局部裁片锁定身份，补全必要隐藏结构，简化到规定画风。分别保存，不回拼。
4. 每次实际调用保存原始图片、真实输入和完整 Prompt，用 `record-call` 留档。没有返回的模型名、种子或参数不写成已执行事实。
5. 检查真实 alpha。工具能给透明 PNG 时保留；若已发现 RGB 棋盘格等失败，后续实际 Prompt 明确改成单一纯色底，避免保留互斥背景要求。按当前工具规则和已有授权使用本地透明化；有授权不重复确认。
6. 用 `cutout` 或 `register` 登记候选，逐项复核实际图片。只修失败对象并保留原稿；默认每个槽位只生成一次，美术问题只在最终输出说明；用户明确要求修正时才重试。不要因轻微斑驳无限重抽，也不能降低标准假报通过。
7. 执行验收与图片导出。透明检查通过不代表风格通过。全部调用完成后交付已生成PNG，缺项和未通过项仅在最终输出简短说明，不弹出验收或候选选择。

## 默认交付

只有独立背景 PNG 和选定素材 PNG。默认不制作或交付 HTML、原图对照、额外报告、源图、Prompt、脚本或日志。需要 ZIP 时只打包图片交付目录。

内部保留生成、透明化和复核记录；不因精简交付而跳过检查。图片或规范变化使旧复核失效。回拼、布局和玩法处理等待用户明确进入后续阶段。

## 默认与用户指定规则的优先级

未指定数量、类别或素材清单时，默认22种素材（建筑8、道具6、载具3、角色5）＋1张背景。用户明确指定时，按用户指定规则执行，覆盖对应默认约束；仅指定总数时不强套8/6/3/5配额，指定完整清单时不额外补足22种。未涉及的要求继续沿用默认。
