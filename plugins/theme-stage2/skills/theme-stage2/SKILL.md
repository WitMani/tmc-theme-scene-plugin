# Theme Stage 2 · 独立背景与素材

目标：从一张 Stage 1 成品图得到独立背景和一组可复用素材。正常运行直接完成选材、生成与检查，不把内部清单、Prompt 或每张素材变成额外确认步骤。

## 默认场景实例数量（216）

新主题的数量规划先读取[真实案例数量规则](references/scene-count-policy.md)；配置见[../../runtime/scene-count-settings.json](../../runtime/scene-count-settings.json)。默认216个摆放实例，未明确覆盖时必须大于200；这不改变独立素材种类数。按相近真实case及本次素材占地、地形容量制定逐原型数量，不把原案例的0.64倍率搬入新场景。新scene-plan必须绑定count_policy，逐项合计与target_total一致。用户明确数量和历史运行保留各自契约；普通独立PNG输入的显式一次摆放不自动扩成主题关卡。

## 固定场景尺寸与标尺

2026-09-16 用户要求：“可以固定stage1和2的尺寸 和真实数据一致”。据六个 val_data 案例采用固定制作契约：**Stage 1 成品与 Stage 2 背景均为4096×4096；人物有效高度基准H=128 px，占画布高度3.125%**。这是用户确认的工程规格，不是飞书原文或所有真实角色精确等高的结论。人物体型、帽饰可围绕1H有所差异；建筑、设施与载具按同类样本的H比例规划，独立PNG画布随主体变化，不强制每件4096。

英文Prompt明确square 4096×4096 delivery、ordinary character height about 3.125% of scene height。工具未提供分辨率参数时不能虚构调用参数。工具返回较小正方形图时，保留原始输出，用下述脚本等比重采样为4096交付，并保留其`.size.json`记录；这是已授权的尺寸标准化，不代表原生4K细节。非正方形结果须修正构图，不能拉伸、裁切或加边伪装完整场景。重采样不会纠正人物在画面中占比过大的问题，仍须目视检查构图标尺。

背景登记前运行 `python3 "$PLUGIN_ROOT/runtime/scene_size.py" --source "$RAW_BACKGROUND" --out "$NORMALIZED_BACKGROUND"`。新运行的validate/export会检查4096背景、H=128尺度计划和绑定当前图片及计划哈希的尺度复核；详细字段见执行流程。历史运行保留原契约，用户要求迁移时另建运行，保留原件。

## 场景交接与基础设施

先读[三阶段交接与返工](references/scene-handoff.md)。新运行必须在生图前绑定scene-plan：继承选中Stage 1候选计划，缺失时主动编制并记录数量依据。只选原型不等于只摆一次。背景清场必须保留所选素材需要的铁路、水域、道路及桥接关系；铁路不是装饰栏杆。完成背景后逐项复核基础设施，绑定实际背景和计划哈希；未经验证不得正式导出。

正常PNG导出同时在内部export-records生成Layout交接包（PNG用户交付目录仍只含图片）。它保存背景、透明素材、数量、核心标记、地形依赖和验收指纹；后续Layout用`init --handoff`导入。产物状态是“美术已验收，布局待验证”，不声称场景已闭环。执行命令见[流程](references/workflow.md)。

## 输入与范围

- 每个运行只有一张原始场景图，可用用户附件、明确选定的对话图或可读路径。局部裁片和修正图必须由它派生。缺图时请求补充，不使用内置示例、旧威尼斯图或其他缓存图替代。
- 多张 Stage 1 图只有在用户要求批量时才各自独立处理；不要把不同候选混成一组参考。
- 默认独立素材为22种：建筑8种、道具6种、载具3种、角色5种，背景另计1张。种类按独立原型计算，重复摆放、仅换色或镜像不算新种类；每种归入一个类别，不重复计数。用户明确清单或种类要求优先，示例清单不覆盖默认规则。此规则仅约束种类，不规定每种摆放数量、目标款数量或总实例数。逐类核对8/6/3/5，不能用其他类别补足总数冒充通过。源图不足时报告缺类与缺失原型；完整流水线回Stage 1修正，独立Stage 2请求仅报告缺口，不无依据补造。
- 同款重复、仅换色、镜像不占新名额；固定花箱和门窗留在建筑里。优先主题辨识度、轮廓/功能差异与复用价值。来源不足时报告缺口，不补造图中未见的类型。
- 用户的新要求覆盖对应默认值。讨论方案、创建插件或询问用法不触发出图。

## 美术与背景

遵循包内规范：日韩卡通、正交45度等距视图、角色约2头身。用户最新反馈优先于旧版解释；原图提供身份与主题。

正式版（美术规则 1.6.0）：独立素材沿用 V2 逻辑，背景采用 B 档大形体分面，同时合并内部小形状与纹理。V3 试验中的额外反面图和定向 Prompt 不作为默认输入或默认规则。

独立素材采用 V2 规则：
- **描边**：逐部件取紧邻填色略深的同色相。蓝部位深蓝线、绿部位深绿线、木色部位棕线、浅色部位暖灰线；不能整件套一条黑/棕/紫线。不同色区可换线色，线宽与透明度保持稳定。
- **体积**：克制但可读，保留顶/正/侧面、厚度、圆润形体与遮挡；允许少量低对比明暗面和局部接触阴影。不能压平为纸片或图标，也不做厚重3D、强黑影和高光亮边。
- **造型**：增加可见的卡通夸张，如放大屋顶、门洞、轮子或头部，主体更紧凑、圆润或有轻微弯曲；保留原型身份和功能，不破坏支撑、连接与解剖结构。
- 保持颜色明亮、细节适量、色块干净；不能将“无渐变”误解为“没有任何明暗面”。不编造文档未定义的相机角、比例容差或线宽硬阈值。

背景采用 **B 档大形体＋简洁明暗**：
- 每个连贯形体以主色和一个主要暗面说明朝向或下侧；同一结构面内不再叠加条带、小分面、树皮斑纹或亮斑。保留顶/侧、遮挡和桥岸厚度。仅用户要求 C 时增加一个宽亮面；不是全图限色。
- 同时减少内部形状数量：叶团合并为少数大轮廓，草丛芦苇按整簇概括；石块只留主要结构面，桥面省略密集砖木缝，水面保留少量宽流纹和细柔泡沫。仅降低明暗对比不算简化完成。
- 优先保障内部连续可排布空间；非交互树木、植被、石堆允许删减、归并与向画布外缘迁移，不锁定数量位置。保留地形高度、河道、桥数位置和接岸。地面保留宽阔环境色区，瀑布水花及远景氛围保留；简化内部刻画。
- `BG_VOLUME_BALANCED`、`BG_DETAIL_BALANCED`、`BG_FORM_GRANULARITY` 分别复核明暗、纹理与形状粒度。已展示的 B 是比较候选，不自动视为所有项目通过。
- 具体判断与 E/B 改进记录见 [背景 B 档规则](../../runtime/docs/BACKGROUND-B-RENDERING.md)。

背景以少量外围主题植被、水流波纹、岸边泡沫、瀑布与柔和环境色差保留环境特征，不做裸地平涂地图。移除建筑、人物、载具、独立设施及多余围栏包边；保留地形分界、必要侧面、桥面桥洞与接岸。水面泡沫不属于物理包边。背景环境层次不套用素材的纯色块限制。

背景必须执行 [可排布空间规则](../../runtime/docs/BACKGROUND-PLACEMENT-SPACE.md) 与 `BG_PLACEMENT_SPACE` 独立验收。先识别内部放置区，再清除非交互立体装饰及侵入投影；外围只留适量装饰，不把删掉的物件全部搬到边缘。“边缘”指画布外缘，不是每块内部地块边缘。道路、岔口和桥头保持净空；结构性地形例外需说明用途。此规则覆盖旧版树木数量位置保留要求。

## 素材相对尺度（必须执行）

采用[官方案例尺度规则](../../runtime/docs/ASSET-SCALE.md)：官方同类素材确定相对大小，Stage 1 确定身份与主题造型。人物为1H；维京建筑高3.2–5.5H、童话建筑3.1–4.3H、科幻建筑1.7–4.2H；宝箱/铁砧约1.0–1.2H，较大酒桶架约2H；童话载具高1.7–3.5H，纸船宽约5H。这些是样本参考范围，特殊对象按同类依据单独记录，不作为所有主题硬阈值。

每次运行先定H及逐件目标尺寸，生成后按非透明主体包围盒等比校准，再登记最终PNG和重新复核。不得统一每件画布占比或最长边；不得仅凭Prompt声称比例正确。内部保存尺度计划、测量及同倍率对照，尺度通过后才正式导出；现有CLI通过不等于跨素材尺度通过。完整测量口径、128px工程默认标尺、例外与复核流程必须读取上述规则。

## 执行

1. 查看本次原图，选择代表性对象，记录原型归组、来源范围和取舍理由。按 [执行流程](references/workflow.md) 准备运行目录与英文 Prompt。
2. 使用当前可用的内置图像生成工具，每个背景或原型独立调用，默认采用**全量并发**：输入准备完成后，一次性提交本次全部素材和背景的独立图像调用（默认22个素材＋1张背景，共23个），不人为分成4张或8张批次。用户明确指定更低上限或工具明确声明上限时遵从；明确限流或并发错误时才逐级降低后续调度并发。先统一选材、尺度计划、Prompt与输入路径，再按[并发执行规则](references/workflow.md#并发生成调度)调度；独立调用不意味着串行等待。有 `imagegen` 技能时按其工具协议执行。不要用代码图形代替素材，不把一次多宫格当成多个独立资产，不擅自切换 API/CLI 生成后端。
3. 背景从原图去物、补全被挡地面并去除围栏包边；资产以原图和自己的局部裁片锁定身份，补全必要隐藏结构，简化到规定画风。分别保存，不回拼。
4. 每次实际调用保存原始图片、真实输入和完整 Prompt，用 `record-call` 留档。没有返回的模型名、种子或参数不写成已执行事实。
5. 检查真实 alpha。工具能给透明 PNG 时保留；若已发现 RGB 棋盘格等失败，后续实际 Prompt 明确改成单一纯色底，避免保留互斥背景要求。按当前工具规则和已有授权使用本地透明化；有授权不重复确认。
6. 用 `cutout` 或 `register` 登记候选，逐项复核实际图片。只修失败对象并保留原稿；默认每个明显失败槽位做一次定向重试，用户要求继续时调整范围。不要因轻微斑驳无限重抽，也不能降低标准假报通过。
7. 执行验收与图片导出。透明检查通过不代表风格通过。无法修复时简短说明缺项/未通过项；用户要看候选时可展示实际 PNG 并明确候选状态，不称其正式合格。

## 默认交付

只有独立背景 PNG 和选定素材 PNG。默认不制作或交付 HTML、原图对照、额外报告、源图、Prompt、脚本或日志。需要 ZIP 时只打包图片交付目录。

内部保留生成、透明化和复核记录；不因精简交付而跳过检查。图片或规范变化使旧复核失效。回拼、布局和玩法处理等待用户明确进入后续阶段。
