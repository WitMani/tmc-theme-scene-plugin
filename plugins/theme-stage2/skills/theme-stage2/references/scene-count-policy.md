# 默认实例数量与真实案例依据

2026-09-17 用户要求：“默认摆放的数量……至少是200以上，你可以根据真实case制定一下”。这是用户的制作默认值，不是原美术文档要求。

## 当前设置

- 新主题完整场景默认 **216个独立摆放实例**；未明确覆盖时下限为 **201**（严格大于200）。同一素材重复24次计24实例；背景里的桥、树、河流不计入实例数。素材种类仍按选材规则，不生成216种PNG。
- 216来自六例中最小的超过200的真实案例NO_Sheffield_17。默认216是制作决策；不能声称所有真实关卡均超过200，或216已经在任意背景容量验证通过。
- 已明确的用户数量优先，包含小于201的单次任务；记录原话为user_override。历史运行保持原计划，不静默升级92/192件。
- 未明确玩法时count_multiple=1；用户明确要求三消/沿用三消时为3，每原型数量是3的倍数，总量也须匹配。默认216兼容三消，但该默认不意味着已选择三消玩法。
- 始终维持4096场景、人物H128、校准素材scale1.0，不以缩小、删核心原型、虚构实例或提高数量容差满足目标。

## 制定每种素材数量

1. 从可见原型、地形依赖选择相近案例：童话带车优先参考Vondelpark/Wonderland；木屋村落可参考Nidaros/Sheffield；科技城市参考OrbitCity。记录选择与差异。不得把OrbitCity建筑占比或Sheffield车辆零数强套给所有主题。
2. 以216为总目标，把参考类别映射到本次原型；按真实PNG占地、需要的道路/水域、可用地块和辨认空间调整类别比例，编制逐ID整数数量与authored依据。车数量由道路容量约束，不能机械提高到统一百分比。保留所有核心原型。
3. 在Stage1草图、Prompt和scene-plan里使用同一实例计划与密度意图。Stage2继承该计划；纯素材任务只保留供下游使用的计划，不自动启动排布。
4. 使用count_policy绑定总目标并校验逐ID数量合计。Layout先容量预检，再实际摆放。预检不通过先检查标注、摆放顺序和地块分配；一次贪心预检不足不代表全局无解。需要改图时回上游，仅按已有预算修失败项。没有足够容量则明确报告缺项，不能自行从216降到198或192。
5. 最终验收既要求精确目标数量，也要求密度、核心组合、道路桥头和辨识度通过。通过几何校验不等于视觉分布自然。若需要变更总目标先形成可追溯新计划，跨seed保持一致；低于201只能用用户明确覆盖。

## 新场景计划字段

```json
"count_policy": {
  "id": "scene-count-200plus-v1",
  "mode": "default",
  "target_total": 216,
  "count_multiple": 1,
  "basis": "用户默认200以上；选216参考Sheffield_17；本主题逐原型分配另有依据"
}
```

根据案例另定超过200的目标时mode=case_based，并写reference_case为上表之一及具体basis。用户明确数量时mode=user_override并写user_instruction原话。三消时count_multiple=3并写gameplay_basis。历史无count_policy的计划仍按原显式数量校验；所有新主题计划必须填写，不得借历史兼容分支逃避默认值。
