# 素材相对尺度 · 官方案例基准

2026-09-16 用户要求将官方案例素材的相对大小写入 Stage 2。以下是该批样本的测量与本插件采用的执行规则，不是官方发布的通用规格，也不是原美术文档的原文。

## 样本与测量口径

来源：用户提供的 `level_data 3/val_data`，包含 NO_Nidaros_3、NO_OrbitCity_1、NO_Sheffield_14、NO_Sheffield_17、NO_Vondelpark_13、NO_Wonderland_9，共95个素材文件（含跨关卡重复款，不代表95个独立原型）。逐文件数据见 `official-scale-measurements.json`。插件运行不依赖原始样本目录；样本不能替代本次 Stage 1 输入，也不自动作为生成工具的图像参考。

测量 alpha > 16/255 的可见主体包围盒，排除透明留白；同一次运行使用相同阈值。包围盒可能包含帽子、武器、附件及残留效果，异常对象需视觉复核，不能把测量值当成人体解剖高度。H 为每个关卡人物可见高度中位数。六关 H 依次为127、120、125.5、124、127、131.5 px。

该批 level.json 均记录 uniformScale=0.64，说明数据配置采用整组统一缩放；不据此宣称已验证游戏引擎内部实现，也不把0.64规定为新主题固定倍率。

## 参考范围

| 对象 | 相对尺寸参考 | 适用说明 |
|---|---|---|
| 普通人物 | 基准1H | 角色之间保留体型、帽饰差异，不逐个强制等高 |
| 维京建筑 | 高3.2–5.5H | 按房屋、塔架等具体功能选取 |
| 童话建筑 | 高3.1–4.3H | 保留夸张轮廓 |
| 科幻建筑 | 高1.7–4.2H | 低矮舱体与高塔分开选择 |
| 宝箱、铁砧 | 高约1.0–1.2H | 采用便于辨认的游戏化比例 |
| 酒桶架等较大设施 | 高约2H | 具体同类对照，不套用到所有设施 |
| 童话载具 | 高约1.7–3.5H | 仅该主题样本；车、船、气球分开判断 |
| 纸船 | 宽约5H | 长条对象优先约束宽度，同时复核高度 |

以上为样本参考范围，不是每类对象的无条件硬上下限。地形块、围栏、悬空气球、特长载具及巨型角色需单独选标尺，记录理由；不能把所有 prop 当成小设施。其他主题选择功能与轮廓最接近的官方类别，明确类比依据，不编造未观察到的官方范围。

## 每次运行必须执行

1. **官方同类素材确定相对尺度，Stage 1 确定身份与主题造型。** 不直接继承 Stage 1 生成图中可能失真的人、房、载具比例。背景保留既定地形规则；本规则不授权回拼或修改地形。
2. 2026-09-16 用户确认固定Stage 1与2尺寸：背景画布固定4096×4096，H_px固定128，alpha_threshold固定16。无人物主题也用虚拟1H。高清原稿可独立保留，但不能只提升交付素材尺寸而不同比改变背景；当前固定交付不使用额外质量倍率。这是用户确认的制作规格，不是官方统一硬规格。
3. 在运行目录保存内部 `scale-plan.json`：记录 H_px、测量阈值及每件资产的 id、参考类别/依据、目标宽或高（以H计）、主约束轴、预期另一轴范围、例外理由。不要假定 prepare 会自动保存自定义字段。实际英文 Prompt 写入目标相对尺度，但 Prompt 不能替代输出后的测量。
4. 生成和透明化后，用 `run.py calibrate --run <RUN> --id <ID>`（或 `--all`）做**单件等比缩放校准**。主轴目标像素=目标H倍数×H_px；缩放系数=主轴目标像素/实际主轴像素。宽高使用同一系数，不拉伸，不统一画布尺寸或统一最长边。另一轴明显不符时复核造型或参考选择，不能非等比硬凑。透明留白由命令在校准后添加，不参与尺度计算。
5. 命令保留原生成图与透明化图，把缩放后候选写到 `calibrated/<id>/<签名>/` 并附 `calibration.json`；同时在 `scale-review.json` 记录校准前后包围盒、目标、实际像素、缩放系数与文件哈希，条目状态为 `unreviewed`。执行者检查轮廓、描边和透明边缘并填写例外说明；质量不足时重做，不靠严重放大低清图凑尺寸。
6. 校准后的PNG由命令自动 register，之后重新生成/填写美术复核表。旧图通过记录不可套用；计划或图片变化后命令会把旧条目重置为未复核。用 `run.py scale-contact --run <RUN> --out <PNG>` 生成同倍率并排对照（附1H标尺条），整张图可统一缩放，不能每件单独填满格子；检查人物—建筑—设施—载具关系后再把 `status`/`reviewer`/`observation` 填为实际目视结论。默认不交付对照图或内部JSON。
7. 尺度复核通过后才导出。跨资产尺度是执行者必须完成的额外验收；新运行的 validate/export 自动读取 scale-plan/scale-review，校验固定背景尺寸、标尺、每件主轴有效尺寸及复核绑定的计划与图片哈希；视觉比例仍由执行者复核。未完成校准或存在未解释偏差时只能交付标明状态的候选。

交付PNG已具有相对尺度。后续Layout默认按已校准交付素材scale=1.0导入，不自动套用历史0.64；个别改比例需要重新记录理由并复核。该规则从新运行及用户要求采用新尺度规则的续跑开始应用，不自动修改已有交付图片。
