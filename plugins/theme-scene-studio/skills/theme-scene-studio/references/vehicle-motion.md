# 载具运动：输入与背景路网规则

来源：2026-09-23用户要求Stage 1“也要用户输入是否有运动载具运动，和摆放layout的harness的运动载具这部分对齐”，运动规则参考飞书《美术和关卡设计的setting补充》第二部分“载具运动规则”（动画实现：水平翻转；运动规则：避开掉头情况皆可行，转弯直接水平翻转资源）。示意图见 [vehicle-motion-reference.jpg](vehicle-motion-reference.jpg)、[vehicle-mirror-reference.png](vehicle-mirror-reference.png)，只作视觉参考，不复制其中路线、字母或车辆。

## 输入：载具是否运动

与tmc-level-layout的`--delivery-mode auto|motion|static`取值一致，在规划阶段只决定一次：

| 用户输入 | requested | mode |
|---|---|---|
| 明确要求载具运动/会动/跑起来 | `motion` | `motion` |
| 明确要求载具静止/不动/静态 | `static` | `static` |
| 未说明 | `auto` | 清单含载具类原型（vehicle / boat / rail_vehicle / submarine / aircraft）即`motion`，否则`static` |

- 未说明时不追问，开工时一句话告知采用结果，例如“清单含载具，按Layout默认规则设计为运动载具路网”。用户明确说法优先，记录原话。
- 用户要求“把背景改成车能跑”“按运动规则改图”视同`motion`。
- `motion`时列出实际运动的载具原型`moving_vehicle_ids`，默认全部载具类原型；用户指定只让部分载具运动时按其指定，其余载具在`static`规则下需有停放地面（`platform`：停车场、码头等），不能停在路上或水里。
- `static`时不适用下文路网限制，道路仍按[场景生活逻辑](scene-life-logic.md)服务目的地，可以有合理尽端路。
- 选择写入scene-plan顶层`delivery_policy`，由`scene_contract.py --require-delivery-policy`校验；下游Layout用同一mode传`--delivery-mode`。Stage 1不验证运动可行性，只把路网设计成可运动，最终以Layout `feasibility`与tmc-vehicle-motion `motion-validate`为准。

## 动画实现（决定路网能怎么画）

- 载具贴图保持原有正交3/4视角和统一比例，运动时只平移和水平镜像；不旋转、不竖直翻转、不压扁、不拉伸、不斜切。
- 转弯时直接切换到出方向对应的水平镜像，不做旋转过渡。所以同一张贴图只能表现“往左”和“往右”两族方向。
- 3/4贴图只露出车头。水平镜像不能把正面变成背面，一直往屏幕上方开会像在倒车。

## 运动规则 → 背景路网要求（mode=motion）

1. **不能掉头**：普通转弯、Z字折线、绕街区的环线都可以；在路尽头原路返回不可以。不画掉头圈、回车场或只能倒回去的尽端路。
2. **每个路端都有去处**：每条行车路（船为航道、火车为轨道）的端点只能是：①延伸出画布边缘（首选，出入口可在四边任意位置，参考图A/B/C/D）；②接入另一条路形成路口或环线；③完全消失在前景遮挡物之后，遮挡物需足够大、能盖住整辆车（山崖、隧道口、成片高树等真实前景物，不是装饰小物）。其余端点都算开放尽端，会被下游排除。
3. **路段方向**：主路沿共同正交相机的两条地面轴（屏幕斜率约±0.707）铺设，这是车身自身的斜向，路宽取1–2.5倍车宽即可通过。尽量避免长的屏幕竖直或水平路段：不旋转的车在竖直段横向伸出约半个车长，竖直路需要接近车长的宽度，会突破2.5倍车宽的上限。确需竖向连接时做短段，或改为沿地面轴的折线。
4. **转弯与路口**：转弯发生在清晰的路口或折点，转角附近留出车身转向所需的宽度，不在窄处急折。路口不要被建筑、桥墩或摆放主体挤窄。
5. **车流方向**：优先把路网组织成从画面上方边缘进入、向下方或两侧边缘离开的贯通路线，这样车辆多数时间朝向观众。需要上行的环线、上坡段时控制长度；没有用户提供的背面贴图时不依赖长距离上行路线。
6. **连续与完整**：路面在桥头、路口和画布边缘保持连续与等宽，不被栏杆、台阶、摆放物、装饰或遮挡物切断；台阶不能作为车道。桥面能让同类载具通过；船的航道不被桥墩、码头堵死；铁路是功能地形，不画成装饰栏杆。
7. **车道空间不算摆放容量**：行车路和航道只给运动载具使用，不能同时计作其他主体的摆放地块或调整余量；运动载具也不在路上停放。点击区仍为主体，路网服务摆放空间，不把大地块切成窄条。

## 落实位置

- **草图**：`band`路网沿地面轴画，路端延伸到画布外或接入其他路；设计说明逐条记录每条行车路的两端（edge / junction / occluder）、服务的载具、宽度依据与车流方向。
- **英文prompt**：`mode=motion`时加入模板中的VEHICLE MOTION ROUTES段，并填写本候选的实际路网；`static`时删除该段。
- **成品检查**：在同一次集中检查中查看有无开放尽端、需要掉头的路段、长竖直窄路、在路口/桥头/画布边缘断开的路面，以及遮挡物能否盖住整车；按具体位置记录。明显违规沿用每槽位最多一次成品修正，不另加预算。
- **scene-plan**：`delivery_policy.route_plan`写明路网出入口、路口/环线与遮挡出入口；对应的`infrastructure.description`也写清连通与路宽。
