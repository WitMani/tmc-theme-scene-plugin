# Stage 1 并发生图调度

默认尽可能全量并发提交已就绪的独立成品调用，不固定4张或8张上限。单主题3张同时提交；多个主题全部就绪时共3T张一次提交。仅处理本次用户选定主题，不擅自扩展主题或候选数量。

## 先满足依赖，再并发

- 查看当前参考组，确定统一镜头，制作并检查辅助线；同组同镜头复用一次辅助线，不为并发重复制作。
- 按layout-sketch.md完成每主题A/B/C三张草图的设计、校验与目视审核。该主题三张全部通过后才能启动该主题成品；不能为提速跳过审核或将未审草图送入生成。
- 独立主题的准备可以推进，各主题就绪后立即提交三张候选，不等待已启动主题的成品全部返回。最终成品不能早于其参考、辅助线和草图准备完成。

## 独立输入与调用

- 各候选固定theme_id、candidate_id、完整英文Prompt、按序排列的参考绝对路径、当前已审核草图版本和独立输出文件名。所有本地输入先实际查看。
- 优先以referenced_image_paths显式绑定完整干净参考组、共享辅助线及当前候选草图；避免并发依赖“最近几张图”。A/B/C和不同主题不得串接成品作为参考。
- 本地路径不齐全时遵从图像工具可用机制；若近期图片引用不能可靠区分并发输入，先取得稳定路径或仅对这些槽位使用可靠串行方式，不漏图、不猜关联。
- 使用可用工具编排并发发起独立内置image_gen调用，例如对全部就绪任务使用Promise.allSettled并逐件捕获结果。遵从当前工具的调用与等待协议，保留运行中的执行上下文；所有已启动调用收敛前不结束脚本或交付。一个失败不取消其他调用。
- 一张图一次调用，禁止多宫格替代候选，不切换API/CLI、不降低画质或增加候选数量。并发请求数不是服务端实际计算并发数，不承诺固定加速倍数。

## 保存、限流与验收

- 按绑定ID接收工具真实输出路径，不按完成顺序猜A/B/C。每个任务保存到自己的文件，修正另存版本；主流程为共用manifest和比较索引的唯一写入者，串行合并记录，避免覆盖。
- 工具明确声明并发上限时遵从。明确返回限流或并发错误后，后续调度按已知上限；未知时降至8，再按需降至4、2或1。当前已低于某档时继续降低，不因降档反而增加并发。
- 降档后等待在途数低于新上限再补位；遵从明确重试等待时间，不取消或重复提交状态未明的请求。慢响应不等于限流；内容或输入错误仅影响该槽位。
- 已成功图片不重跑。失败沿用每槽位最多一次额外尝试的预算，无法修复则报告缺失或未合格，不无限重试。
- 可在其他请求在途时逐张查看已完成图片；最终仍按原规则检查画风、镜头、草图一致性和三候选实质差异，不能以并发完成代替验收。记录实际调用状态与失败信息，不把配置更新当作已实测提速。
