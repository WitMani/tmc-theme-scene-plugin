# 生图前的布局草图

生成前读取[size-policy.md](size-policy.md)，落实人物75×130、物件分档、道路1–2.5车宽及大型实例上限状态；草图与交接使用同一尺寸契约。


每个主题先完成 A/B/C 三张布局草图并做一次可用性快检，再开始该主题的成品生图。草图是必须保存、实际查看的图片，不以文字方案代替。仅修改插件或讨论流程时不触发生成。

## 分工与输入

主 agent 查看参考组，确定主题元素、交互用途假设、输出画幅和共同正交镜头，将这些资料及参考图片路径交给布局设计 subagent。有多 agent 工具时实际委派，等待其交付；不另建用户侧任务。subagent 负责布局与草图，不自行生成最终场景或修改插件。工具不可用时由主 agent 按相同步骤完成，明确记录未使用独立 subagent。

## 相机与画风隔离

开始布局前必须读取 [orthographic-geometry.md](orthographic-geometry.md)，使用其中的脚本统一投影。默认45°方位/45°俯角，地面圆、道路宽带、地形与占位都来自同一XYZ坐标；不能将俯视路网拼接到斜视房屋上。绘制投影正确不要求建筑排成网格。

供图只用中性低细节轮廓、平面占地与少量低矮占位表达空间，禁止屋顶样式、门窗、纹理、主题色和硬阴影；少量示意色只能表达用途，不负责画风。文字ID与图例放配套说明。密度和环境关系继承当前参考/用户偏好，不写死建筑数量，也不把点击区主体误解成大块空白。

## 主体摆放优先规划

先读取 [主体摆放空间](placement-space.md)，在草图配套说明中记录各主要区域适用的主体组、计划数量、占地估计、辨识间距与调整余量，再布置设施。审核重点是地块是否真正适合相应主体，是否被道路切碎或被高物遮挡；规划估计不能当作容量验证。主体区、必要通路和调整余量不能重复占用，有用途的留白必须保留。

## 生活动线规划

按 [场景生活逻辑](scene-life-logic.md) 先确定活动地点与连接需求，再布置桥、道路、入口和码头。配套说明记录各桥连接的区域、用途、局部河道与桥向依据，以及必要的高差过渡；不要把统一相机误解成所有设施同向。审核时检查港口进出水路与岸上衔接、道路服务的目的地，并逐桥检查连接关系；另查有无等距港口、重复桥列和反复套用的路网组合，将核心设施关系写入scene-plan。

## 载具运动路网

`delivery_policy.mode=motion`时按[载具运动规则](vehicle-motion.md)画路：`band`主路沿地面轴，路端延伸出画布、接入其他路或止于能盖住整车的遮挡物，不画掉头圈、回车场或开放尽端，避免长竖直窄路。配套说明逐条写明每条行车路/航道/轨道的两端类型（edge/junction/occluder）、服务的运动载具、路宽依据和主要车流方向。快检一并看这些；`static`时按生活逻辑正常处理尽端路。

## 草图交付

1. 为 A/B/C 分别规划点击区、非点击区、道路/水路与主要物件群，保留均衡分布、局部聚集、分区串联的实质差异。先分配宽裕的点击区，再安排少量环境点缀；三张保持同一画幅、镜头及资产尺度。
2. 编写世界坐标scene.json，用打包的 `scripts/orthographic_layout.py render` 输出 SVG/PNG/JSON 和 `.validation.json`；此步骤是新建布局图，不编辑参考图，不需要额外生图调用。草图以共同斜俯视正交方向表达地块与简化体块，不混用顶视图和透视镜头。优先用本地可用矢量渲染工具，不为草图转用外部 API。
3. 用脚本固定中性色区分点击区和非点击区；道路/水域的交互用途另行注明，避免把所有水面都判为非点击区。标注主要物件群占位、桥接岸、连接关系与必要间距。图内不添加文字；区域 ID、颜色图例、对应元素和用途写入配套说明。示意色不代表成品配色。
4. 每张保存原始 `layout-A.scene.json`、脚本校验报告 `layout-A.validation.json` 及 `layout-A.svg`、`layout-A.png`、`layout-A.json`（B/C同理）。原始scene JSON至少包含 candidate_id、画布尺寸、共同镜头说明、区域ID/多边形/交互用途/地表类型、物件群占位、连接关系、用途假设及设计说明。空间坐标是规划数据，不是从参考图测得，也不是运行时碰撞或点击数据。

## 草图可用性快检

使用render已生成的validation结果，不再默认重复跑validate。设计执行者查看A/B/C草图一次，集中确认投影一致、主要物件有放置空间、必要道路/桥梁连接可用，并简短记录明显问题。主流程沿用该结果，不另派审核者或再做一轮相同检查。

发现明确影响成品生成的问题时，只修对应草图并查看改动部分；默认最多一次定向修正，不为轻微布局偏好循环修改。仍不可用时如实标记受影响候选；可用候选继续，最终说明缺项。通过即继续生成，默认不等用户验收。用户明确要求先确认时才按其要求暂停。

## 成品参考与检查

每次生图输入顺序：完整干净参考组 N 张 → 共用正交辅助线图 1 张（启用时）→ 当前候选已审核的布局草图 1 张。默认共 N+2 张，即3–5张。每次只传当前候选草图，不能把三张都传入或把A草图用于B/C。关闭辅助线时共N+1张。

干净图负责画风、比例和细节；已校验草图与相机规格负责投影、地块、空间占比、物件群和连接关系；辅助线仅提供同一规格的近似提示。辅助线与规格冲突时修正辅助线，不扭曲草图去匹配错误线条。明确提示生成器忽略草图的示意颜色、标签、轮廓框与图例，不复制原图布局。草图和辅助线均是软约束；最后逐张对照草图检查点击空间是否被环境内容侵占、连接是否丢失、有无示意标记残留。明显偏差沿用每候选最多一次成品修正上限。

所有输入有本地路径时用文件引用参数；涉及近期图片机制时必须确认完整参考组、辅助线和当前草图都能被纳入工具上限，不静默省略原图或草图，不拼图绕过限制。无法完整引用时说明缺失项并请求重附所需图片。

manifest 每个候选增加 layout_sketch：SVG/PNG/JSON路径、设计者实际角色、审核者实际角色、状态、修订次数、审核记录、最终采用版本。记录实际输入图片顺序。交付时同时链接草图及对应成品，说明实际观察到的偏差；草图不计入3T张成品数量。
