# 为主体摆放预留空间

生成前读取[size-policy.md](size-policy.md)，落实人物75×130、物件分档、道路1–2.5车宽及大型实例上限状态；草图与交接使用同一尺寸契约。


Stage 1为摆放游戏提供场景与可辨识的素材来源。布局优先级为：主体摆放和辨识空间 → 必需的连接设施 → 主题环境装饰。空间规划须同时维持主题逻辑、固定镜头、H130标尺、原型清单与实例目标；不通过缩小素材、减少明确数量或牺牲核心连通来伪造容量。

## 从主体反推地块

- 先按已有原型ID、计划数量、相对占地及地形依赖划分主体群，给建筑等大件保留宽裕地块，再安排角色、道具及载具的适用区域。占地尚无实测PNG时记录为设计估计，不报告精确容量已验证。
- 每个主要摆放区在草图配套说明里写明区域ID、适用主体组、预计分配数量、占地/尺度依据，以及需要保留的间距和调整余量。数量分配与scene-plan一致；Stage 1成品仍不要求生图精确画出每种重复数量。
- 可用地块须足够宽、形状易于组合且可见。避免只剩狭长岸边、尖角地块、建筑背后和被岩壁遮挡的碎片；大面积水面不能代替建筑用地，小块陆地不能代替船只水域。
- 区分主体占地、物件之间的辨识/操作间距、必要通路与尚未占用的调整余量；同一块空间不重复计作容量和必需通道。不给所有区域统一预设像素间距或面积百分比；依据本次主体尺度说明理由，未提供交互规格时只做可见性与空间规划，不冒称通过触控或拖拽测试。

## 背景服务于摆放

- 港口、道路和桥梁围绕主体群提供必要连接，避免道路把大地块切成窄条、多座桥及桥头占满核心摆放面、港口设施侵占全部岸上空间。先保留可用主体区，再决定设施数量、位置和范围；必要设施仍须连续、合理且满足相应载具需要。
- 非必要山体、岩壁、大树和装饰优先退到边缘或缩减，保留少量主题特征；不得遮挡主要主体群、挤掉大件空间，或用碎道具把预留空隙重新填满。
- 背景摆放区保持视觉安静，减少会与可交互主体混淆的装饰性物件和高对比细节。主体轮廓清楚，前后排有可辨识的错位与间隔；具体玩法要求遮挡时以用户要求为准。
- 有用途的空地与调整余量是有效设计，应保留。避免把预留空间误删为“画面不够满”；同时仍清晰展示全部约定原型并保持规划密度，不把Stage 1整张变成无主体的空背景，也不额外复制一套“展示用”主体占用摆放区。

## 审核与交接

草图先核对主体区与设施区的冲突，再看背景生活逻辑和视觉变化。各候选要有可说明的摆放组织差异，例如群落间隔、大小地块组合和连接方式；不能通过更多环境占地制造差异。

成品检查：大件是否仍有宽裕区域，小件是否可辨识，通路与调整余量是否被新增装饰填满，主体是否被高物遮挡，水陆用地是否与计划相符。记录具体区域与可见问题；有明显挤占或碎片化时沿用既有草图修订和成品重试预算，不增加调用预算。

将主体区域分工与余量意图写入已有density.intent/basis及goals.description；相关设施边界与连接写入infrastructure.description，并保持assets的zones/requires与计划一致。不向现有schema的枚举字段塞入自定义区域ID。下游据此保留可用地块与间距，实际PNG占地、mask容量和游戏交互仍需后续验证；Stage 1只交付规划和目视证据。
