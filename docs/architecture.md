# 阶段边界与分发

## 一个仓库，两个插件包

`plugins/theme-scene-studio/` 与 `plugins/theme-stage2/` 各自包含 `.codex-plugin/plugin.json`、技能入口和所需资源。市场仅列出这两个安装位置，不承担生成编排。

| 边界 | Stage 1 | Stage 2 |
| --- | --- | --- |
| 职责 | 根据主题探索三种场景布局 | 从一张场景图重建背景和代表性素材 |
| 输入 | 主题与可选参考组，可使用自己的默认图 | 用户选定的一张完整场景图，没有默认场景 |
| 图像生成 | 内置图像工具，每候选独立调用 | 内置图像工具，每背景/原型独立调用 |
| 运行数据 | 自己的候选、Prompt、manifest | 自己的源图副本、裁片、调用及图像绑定复核 |
| 本地依赖 | 技能与随包参考资源 | 自己的 Python 依赖、runtime、profiles、规范快照 |
| 交付 | 候选图片及记录 | 默认仅背景与素材 PNG |

Stage 2 所说的“Stage 1 场景图”是一种输入角色，不是软件依赖。它只接收图像文件；无需解析 Stage 1 的文件夹命名、主题编号、候选编号或 manifest。Stage 2 自己产生的局部裁片用于定位物件，不是额外的场景输入。

## 版本与规则

两个插件保留独立名称和版本。本次导入 Stage 2 的当前正式版插件及美术配置 1.4.0；插件版本和美术配置版本含义不同。当前 `playcity-art-v1.json` 指向的内容与 1.4.0 一致，历史配置保留用于追踪既有运行。

Stage 1 的美术规则留在自己的技能包。Stage 2 的背景规范和素材 V2 规范留在自己的 runtime。即使两阶段都有描边、镜头等概念，也不抽取会联动修改两阶段的公共美术配置。后续只有出现稳定且实际复用的纯文件工具时，再考虑独立公共库。

Stage 2 不需要联网读取规范或登录飞书。规范快照、示例和反馈都随包分发，示例不自动作为生成输入。

## 旧入口迁移

原根目录下的 `.codex-plugin/`、`skills/` 与 Stage 1 案例整体移到 `plugins/theme-scene-studio/`，技能和资源保持原有相对关系；详细 README 留在该插件目录。根 README 改为双插件导航。

仓库根目录现在是市场入口，不再作为一个包含所有技能的插件安装。旧的 `skills/theme-scene-studio/` 手动复制路径改为 `plugins/theme-scene-studio/skills/theme-scene-studio/`。Stage 2 需要整个 `plugins/theme-stage2/` 插件包，不能只复制 SKILL.md，因为它还需要自身 runtime 和 scripts。

从旧市场切换来源属于安装迁移，不会自动修改已有安装。个人开发目录和现有生成任务不受本次仓库整理影响。

## 分发验证

仓库测试检查两个市场路径是否匹配各自 manifest、技能目录是否隔离、随包链接是否存在，并将 Stage 2 单独复制到临时目录，从另一个工作目录运行全部回归测试。这样可以发现依赖仓库根目录、Stage 1 目录或个人开发路径的问题。

生成结果与用户批量运行文件不进入插件源代码。PNG 透明化与处理测试仅说明程序行为，不代表新生成图片已经满足美术要求。
